把标书
当账本写

投标失败通常不是因为写得不好，而是因为 漏了一条要求、编了一个参数、 承诺了一句不该承诺的话。v2 把这三种事故变成三门可被机器拦住的闸机： 条目化台账、零发明标记、双轨核查。

Why v2

v1 能用，但会在三个地方
让你误以为"已经做完了"

这三个问题都不是"功能不够"，而是"通过得太容易"。看上去都绿了，实际上什么都没查。

BLIND SPOT 01

声明式覆盖

章节头写了 > 覆盖条目：R-012，正文一个字没写。v1 的覆盖率算 100%，报告全绿。

v2 区分声明级与实质级覆盖，只在声明出现的条目直接 COV-02 阻断。
BLIND SPOT 02

正则失配的假通过

覆盖率用 \bR-\d{3,}\b。中文算 \w，"条目R-001"匹配不到——覆盖率可能恒为 0 或恒为 100。

改成 lookaround，并补 T01 回归用例锁死这个行为。
BLIND SPOT 03

静默降级

没装 python-docx 时返回 [跳过] 字符串，它被当作正文参与扫描。报告"正常"，数据全错。

改为显式 InputError + 退出码 2：宁可失败，不给假绿。
Routing

先路由，再执行

v1 不管你问什么，都跑六阶段。一句话的请求也要走完全流程——慢，且容易在无关步骤上跑偏。v2 先判断你要的是哪一种活。

M1 · 读标 S0 → S1

先把文件读懂

"这份招标文件讲了什么？红线在哪？"

交付：台账 + 废标红线 + 评分点表
M2 · 编标 S0 → S5

出成稿

"帮我写技术标 / 商务标。"

交付：八件套
M3 · 体检 S4 双轨

会不会废标

"复核一下这版有没有坑。"

交付：核查报告 + 整改清单
M4 · 定点 单点

就问一句

"这句话能不能写？算不算负偏离？"

交付：结论 + 原文依据
Pipeline

六阶段，四个闸机

与 v1 最大的差别不是"多了几步"，而是每一步都有失败动作：门禁不过时，正确做法是停下来说明缺什么，而不是继续往下写。

New

六块新能力，
都指向同一个问题：能不能核对

投标这件事，说不清就等于没做。新增能力全部以"可被第三方复核"为标准设计。

评分作战表

把评分办法拆成"得分点 → 分值 → 证据 → 章节 → 把握度"，一张表回答三个问题：哪些分确定拿不到、哪些分还没落点、离满分差多远。

  • 无承载章节 → SCORE-01 阻断
  • 证据为空 → SCORE-02 阻断
  • 可达分 < 70% → 竞争力提示

复用污染扫描

比"凭空编造"更危险的编造变体：旧项目名、旧编号、内部用语没删干净。读起来通顺，直到资格性审查被废标。

  • 旧编号 → POLL-01 阻断
  • 旧项目名 → POLL-02 警告
  • "按上次标书" → POLL-03 阻断

机器可读报告

validate.json：每条发现带 id、规则号、定位、证据、整改建议，直接接 CI 与台账。

强制强度五级

禁止 / 必须 / 应 / 宜 / 可，替代 Y/N 二分——整改时先改哪条，不再靠感觉。

溯源三件套

原文摘录 + 行号 + 版本标记。随机抽三条，30 秒内找不到原文，就是溯源不合格。

交付契约与异常边界

固定目录（00-输入 到 50-交付）、命名规则、Issue ID（F-001）、十节核查报告结构；外加 14 类真实异常的处理口径：扫描件、加密文件、超长标书、多版本补遗、联合体、分包、电子标 CA、涉密项目…… 每一类都明确"怎么降级、怎么标注、什么情况下必须停"。

Quick start

三步，全部零依赖

只要 Python 3.8+。读 .docx 才需要可选的 python-docx，不装也能跑 .md / .txt。

1 · 抽取要求台账 
# 一条命令把招标文件变成可勾选的台账
python scripts/extract_requirements.py --input 招标文件.md --output requirements.csv --ver v1

# 输出：原始条目 22 / 去重合并 3 / 主条目 19 / 必答 12 / 需澄清 2
2 · 交付前双轨核查 
# exit 0 = 通过；1 = 有阻断项；2 = 输入有问题
python scripts/validate_bid.py --bid ./20-正文 --req requirements.csv \
  --map outline-map.csv --score scoring-matrix.csv \
  --project "本项目名称" --project-no "KM-2026-1234" \
  --report validate.json
3 · 验证脚本在你机器上行为一致 
python -m unittest discover -s tests -v

投标文件是要约文件。
写进去的每个数字，都是义务。

所以这个技能不教你"怎么写得更漂亮"，它只保证一件事：你说已响应的每一条，都能被指认、被核对、被复现。
