# 交付前合规核对清单（Compliance Checklist）

用途：投标文件装订之前的**最后一道闸门**。
建议打印出来逐项打勾——**不勾完不签字，不签字不送印**。

标注 ⚠️ 的项是**高频废标点**，一旦出问题往往无法补救。

---

## A. 资格与准入（不满足即出局）

- [ ] A1 营业执照在有效期内，经营范围覆盖本项目内容
- [ ] A2 全部资格条件逐条自查，且有对应证明材料
- [ ] A3 ⚠️ 资质证书在有效期内（重点查年检、换证、有效期截止日）
- [ ] A4 财务报告/审计报告年度符合要求
- [ ] A5 社保、纳税证明的**所属期间**符合要求（常见错：提交的是上上月的）
- [ ] A6 无重大违法记录声明已按格式出具
- [ ] A7 联合体投标的，联合体协议已签署且分工明确（若不接受联合体，确认我方非联合体）
- [ ] A8 不存在被列入失信名单、政府采购严重违法失信名单的情形（自查并留存截图）

---

## B. 符合性审查（废标高发区）

- [ ] B1 ⚠️ 投标文件份数：正本 \_\_ 份、副本 \_\_ 份、电子版 \_\_ 份（逐个核对，少一份即废）
- [ ] B2 ⚠️ 装订方式符合要求（胶装/骑马钉/活页——**活页常被禁止**）
- [ ] B3 ⚠️ 密封与标记：封套标识、骑缝章、封口处盖章是否齐全
- [ ] B4 ⚠️ 投标函已按格式填写并加盖公章、法定代表人签字（或授权代表签字 + 授权书）
- [ ] B5 ⚠️ 法定代表人授权委托书已附，且被授权人签字与身份证一致
- [ ] B6 ⚠️ 报价表已填写，大小写金额一致，无涂改（涂改处是否需盖章确认，查招标要求）
- [ ] B7 投标有效期承诺 ≥ 招标要求天数
- [ ] B8 投标保证金已缴纳，形式（转账/保函）与金额符合要求，凭证已附
- [ ] B9 目录页码与实际页码一致
- [ ] B10 全文无他人名称、他项目名称残留（**模板复用的头号事故**）
- [ ] B11 要求的格式文件（投标函、报价表、承诺函）使用招标方提供的**原格式**，未自行改动版式

---

## C. 技术响应完整性

- [ ] C1 ⚠️ `requirements.csv` 中 mandatory=Y 的条目**覆盖率 = 100%**（跑 validate_bid.py 确认）
- [ ] C2 点对点应答表已逐条填写，无空行、无"见方案"式敷衍
- [ ] C3 ⚠️ 应答表中无"部分响应""基本满足"等灰色表述（会被判不响应）
- [ ] C4 技术偏离表已填，无偏离的项已明确写"无偏离"
- [ ] C5 招标指定的品牌/型号/标准已响应，或已提出偏离并说明理由
- [ ] C6 技术参数无低于招标门槛值的情况（逐项比对，特别注意"≥/≤"方向）
- [ ] C7 ⚠️ 所有 `[待确认]` 标记已清零（脚本检查 + 人工全文搜索双确认）
- [ ] C8 引用的标准号、协议号准确（GB/T 28181、GB 50348 等，错号等于没引用）

---

## D. 商务条款

- [ ] D1 工期/交货期承诺 ≤ 招标要求
- [ ] D2 付款方式接受招标条件（或已明确偏离并说明）
- [ ] D3 质保期 ≥ 招标要求
- [ ] D4 履约保证金接受比例与形式
- [ ] D5 违约责任条款已由商务/法务确认接受
- [ ] D6 知识产权归属条款已确认（定制开发类项目重点）
- [ ] D7 保密条款已确认
- [ ] D8 ⚠️ 报价未超最高限价，未低于成本价（低于成本需提供说明）

---

## E. 服务与实施承诺

- [ ] E1 售后响应时限、到场时限已由服务部门核定（**不是投标组自己写的**）
- [ ] E2 服务网点覆盖项目所在地（承诺的到场时间与网点距离是否匹配）
- [ ] E3 备件供应方案与库存承诺已核实
- [ ] E4 培训方案的人天、人数、场地责任划分清晰
- [ ] E5 项目经理与关键人员已确认可投入，无一人多项目冲突
- [ ] E6 实施进度计划与招标工期匹配，关键里程碑清晰
- [ ] E7 验收标准与招标验收条款一致

---

## F. 一致性交叉检查（最容易被忽略）

- [ ] F1 技术方案中的工期 = 商务标中的工期 = 进度计划中的工期（三处必须一致）
- [ ] F2 技术方案中的人员 = 人员配置表中的名单
- [ ] F3 应答表中的参数 = 技术方案正文中的参数
- [ ] F4 报价表中的设备清单 = 技术方案中的设备清单（型号、数量逐项对齐）
- [ ] F5 公司名称、项目名称、招标编号全文一致
- [ ] F6 正本与副本内容完全一致
- [ ] F7 电子版与纸质版内容一致（**常见事故：改了纸质版忘了更新 U 盘**）
- [ ] F8 页眉页脚中的项目名称与封面一致

---

## G. 最后一小时清单（送印前）

- [ ] G1 全文搜索框依次搜：`待确认`、`TODO`、`XXX`、`补`、`？？`、`示例`、`模板`
- [ ] G2 全文搜索上一版项目名称，确认无残留
- [ ] G3 目录已重新生成（Word：右键目录 → 更新域 → 更新整个目录）
- [ ] G4 页码连续，无断页、无空白页
- [ ] G5 图表编号连续，图注与正文引用一致
- [ ] G6 打印一份黑白稿检查（彩色图转黑白后是否还能看清）
- [ ] G7 装订后翻一遍，确认无倒页、缺页、夹页
- [ ] G8 密封前拍照留存（封套外观 + 骑缝章）
- [ ] G9 确认递交时间与地点，预留交通与排队时间
- [ ] G10 递交回执/签收单已取回并归档

---

## 使用方式

1. 打印本清单，A–F 部分由**技术、商务、资质三个口分别自查**，交叉签字；
2. G 部分由**一个人独立完成**（不要让写方案的人自查最后一步，会产生盲区）；
3. 任何一项打不了勾 → 记录问题与责任人 → 修复后重新过该项；
4. 清单归档，作为项目过程文件留存（后续质疑投诉时是重要证据）。

---

## 与双轨核查的对应关系（v2 新增）

清单负责**语义**，脚本负责**形式**。不要用清单替代脚本，也不要指望脚本替代清单。

| 本清单区块 | 对应维度 | 脚本可自动检查的部分 | 只能人工判断的部分 |
|---|---|---|---|
| A 资格与符合性 | A 招标合规 | — | 证书真伪、业绩是否同类、人员是否在册 |
| B 技术响应 | D 内容质量 | 覆盖率、仅声明未展开、灰色表述 | 答非所问、参数方向（≥/≤ 写反） |
| C 评分点 | C 评分项 | 评分点无章节、无证据 | 证据是否有效、把握度评估是否乐观 |
| D 商务条款 | B 内部合规 | — | 报价红线、付款比例能否接受 |
| E 服务承诺 | B 内部合规 | 绝对化词（终身/无限/100%） | 服务网点能否覆盖、人力成本 |
| F 一致性 | D/F 质量与文字 | 项目名/编号残留、正副本差异 | 三处工期是否真的一致（需语义比对） |
| G 送印前 | E 格式 / G 完整性 | 占位符、目录页码、章节编号 | 装订、盖章、密封、递交 |

## 合格发现 vs 不合格发现（写报告时的判定示例）

AI 写核查报告最容易犯的错：给了一堆"建议进一步完善"式的空话。发现项必须可整改。

**不合格的发现（等于没提）：**

> 技术方案部分内容不够充分，建议进一步补充完善，提升针对性。

问题：没有位置、没有证据、没有规则、无法验收。

**合格的发现（可直接派活）：**

> - **等级**：BLOCKER
> - **规则**：COV-01（仅声明未展开）
> - **定位**：`20-正文/03-技术标.md` 第 214 行，3.4 节
> - **证据**：该节仅有 `> 覆盖条目：R-019`，正文未出现"级联""GB/T 28181"等任何响应内容
> - **影响**：R-019（mandatory=Y，技术要求 2.1.2）实质未响应，符合性审查存在被判不响应风险
> - **整改**：在 3.4 节补充 ≥80 字响应段，必须包含①支持的级联层级②单域最大接入数③与 R-003 的容量关系
> - **复核**：技术负责人

判断标准：**换一个没参与项目的人，能否只凭这条发现完成整改？** 不能，就是不合格。

## 七维核查矩阵（与旧版 A–G 清单的映射）

v1 的 A–G 是"按文件部位"组织的清单，v2 增加"按风险维度"的视图，两者是同一件事的两种切法：

| 维度 | 关注点 | 典型致命项 | 主要手段 |
|---|---|---|---|
| **A 招标合规** | 资格、废标条款、实质性条款 | 资质过期、业绩不达标、未响应实质性条款 | 人工 + `qualification-check.csv` |
| **B 内部合规** | 报价红线、用章授权、审批留痕 | 报价低于成本、无授权承诺、漏盖章 | 人工 |
| **C 评分项** | 得分点响应与证据 | 有分无证据、评分点无落点 | `scoring-matrix.csv` + 脚本 |
| **D 内容质量** | 针对性、矛盾、口径 | 通用模板直投、工期三处不一致 | 脚本 + 人工 |
| **E 格式规范** | 目录、页码、页面设置、装订密封 | 目录页码与正文不符、密封不合规 | 脚本 + 人工 |
| **F 文字细节** | 项目名、编号、单位、错别字 | 残留旧项目名、金额单位混用 | 脚本（`--project`） |
| **G 完整性** | 章节、附件、签章、份数 | 缺附件、缺签字、份数不足 | 脚本 + 人工 |

**执行顺序**：先跑脚本清 A/C/D/E/F/G 的形式问题，再按 A–G 清单做语义复核。
反过来做（先人工逐条看 60 项，再跑脚本）会做大量无用功。
